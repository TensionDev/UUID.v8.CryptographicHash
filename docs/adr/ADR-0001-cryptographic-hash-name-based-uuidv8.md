# ADR-0001 – Cryptographic Hash Name-Based UUIDv8

**Status:** Accepted
**Date:** 2026-10-07

## Context

UUIDv3 and UUIDv5 provide deterministic, name-based UUID generation using MD5 and SHA-1 respectively.

Modern applications may require stronger cryptographic hash algorithms while retaining the same general name-based UUID model.

RFC 9562 reserves UUIDv8 for application-specific UUID layouts, providing an appropriate space for a name-based UUID mechanism using modern cryptographic hashes.

TensionDev.UUID already models UUID generation using version-specific implementations and accepts the namespace as an input for name-based UUID generation. The UUIDv8 cryptographic hash implementation should follow this existing model.

## Decision

Define a name-based UUIDv8 generation mechanism using cryptographic hash functions.

The mechanism is identified as `TensionDev.UUID.v8.CryptographicHash`.

The namespace and name are supplied as inputs, following the model established by UUIDv3 and UUIDv5.

The UUID is generated by concatenating the 16-byte namespace UUID representation with the UTF-8 encoded name, hashing the resulting bytes with the selected cryptographic hash algorithm, taking the leftmost 128 bits of the resulting digest, and setting the UUID version to `8` and the UUID variant according to RFC 9562.

The initial implementation will support the SHA-2 algorithms:

- SHA-256
- SHA-384
- SHA-512

The hash algorithm is selected by the concrete implementation under `CryptographicHash`; it is not encoded into the resulting UUID.

The resulting value is a UUIDv8 regardless of which supported hash algorithm was used.

## Format

    Namespace UUID + UTF-8 Name
              |
              v
    Cryptographic Hash
              |
              v
    Leftmost 128 bits
              |
              v
    Set UUIDv8 Version and RFC Variant
              |
              v
            UUID

The resulting UUID contains no identifier for the namespace, name, or hash algorithm used to generate it. Reproducing a UUID therefore requires the same namespace, name, and hash algorithm.

## Compatibility

The mechanism is conceptually aligned with the name-based construction used by UUIDv3 and UUIDv5, but is not intended to produce values compatible with either version.

UUIDv3 and UUIDv5 remain unchanged and continue to follow their respective standards.

This mechanism uses UUIDv8 as defined by RFC 9562 and does not claim that the `TensionDev.UUID.v8.CryptographicHash` construction is an IETF-standard UUID format.

## Consequences

### Positive

- Provides deterministic UUID generation using modern SHA-2 algorithms.
- Retains the namespace-and-name model established by UUIDv3 and UUIDv5.
- Uses the UUIDv8 space intended for application-specific formats.
- Fits the existing TensionDev.UUID architecture.
- Allows additional cryptographic hash algorithms to be added without changing the UUID representation.

### Negative

- UUIDv8 values generated by this mechanism are not interoperable with UUIDv3 or UUIDv5.
- The namespace, name, and hash algorithm must be known to reproduce a UUID.
- Different hash algorithms produce different UUIDs for the same namespace and name.
- Digest data beyond the first 128 bits is discarded because a UUID contains only 128 bits.
